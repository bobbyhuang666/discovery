# Stop Policy

## Stop when

- the next-stage objective is clear;
- actors, authority, and essential workflow are understood at the selected depth;
- high-impact, hard-to-reverse decisions are resolved or explicitly deferred;
- P0 behavior has executable acceptance criteria when implementation is next;
- remaining unknowns have a treatment, owner, experiment, default, or revisit condition;
- no unresolved contradiction makes the output misleading;
- the user confirms shared understanding or authorizes autonomous defaults.

## Continue only when

The next action is likely to change:

- scope;
- priority;
- safety or compliance;
- feasibility;
- acceptance criteria;
- rollout or migration;
- investment decision.

## Do not continue merely because

- a low-priority future feature is undefined;
- a reversible visual detail is undecided;
- every possible edge case has not been imagined;
- a metric lacks a precise baseline that can only be measured later;
- the user is fatigued and remaining items are non-blocking.

## Best-effort exit

When the user stops early, produce the smallest honest artifact and clearly separate:

- confirmed decisions;
- defaults;
- unresolved blockers;
- recommended next validation.
